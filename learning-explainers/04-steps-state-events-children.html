04 Steps: State, Events, Children

Bài này dạy cách đọc project 04-steps theo một câu hỏi: khi người dùng bấm nút, dữ liệu nào đổi, React render lại phần UI nào, và component nào chịu trách nhiệm nhận nội dung?

Project: 04-steps File chính: final/src/App.js Nền tảng: React 18.2 trong repo, docs React hiện hành

Mental model của bài này

Vanilla DOM

Bản starter/vanilla.html giữ biến step, rồi gọi updateUIValues() để tự đổi text và class trên DOM.

React

Bản final/src/App.js giữ step bằng useState. Khi gọi setStep, React render lại component và UI được tính từ state mới.

Công thức đọc project này: state hiện tại + event handler -> render JSX mới.

Cây component

App
├─ Steps
│  ├─ StepMessage
│  │  └─ children: message + "Learn how" button
│  └─ Button x 2
└─ StepMessage x 2, ví dụ riêng về children

App không quản lý state của step. State nằm trong Steps, vì các nút, số active, message và panel đóng/mở đều thuộc về một instance của Steps.

Hai state trong Steps

State Kiểu Dùng để render
step number: 1, 2, 3 Số nào active, message nào được lấy từ messages[step - 1], và alert trong nút Learn how.
isOpen boolean Nếu true, render panel steps. Nếu false, expression isOpen && (...) không render panel. 
const [step, setStep] = useState(1);
const [isOpen, setIsOpen] = useState(true);

Event handlers không tự chạy khi render

Trong JSX, onClick={handleNext} nghĩa là truyền function để React gọi sau khi user click. onClick={handleNext()} sẽ gọi function ngay trong lúc render, nên sai cho trường hợp này.

Đúng

<Button onClick={handleNext}>
  Next
</Button>

Đúng khi cần truyền tham số hoặc gọi inline

<Button
  onClick={() =>
    alert(`Learn how to ${messages[step - 1]}`)
  }
>
  Learn how
</Button>

Vì sao dùng updater function?

Project dùng setStep((s) => s + 1) và setIsOpen((is) => !is). Đây là cách nói với React: "hãy tính state mới từ state trước đó". 

function handleNext() {
  if (step < 3) {
    setStep((s) => s + 1);
  }
}
Với nút Next hiện tại, setStep(step + 1) vẫn thường chạy đúng. Nhưng updater function là pattern tốt khi state mới phụ thuộc trực tiếp vào state cũ, đặc biệt nếu sau này có nhiều update trong cùng một event.

UI được tính từ state

Không có đoạn code nào tự add/remove class như vanilla DOM. JSX tự mô tả UI đúng với step hiện tại. 

<div className={step >= 1 ? "active" : ""}>1</div>
<div className={step >= 2 ? "active" : ""}>2</div>
<div className={step >= 3 ? "active" : ""}>3</div>

messages[step - 1] dùng step - 1 vì user nhìn step bắt đầu từ 1, nhưng array index bắt đầu từ 0.

children trong StepMessage và Button

children là phần JSX nằm giữa tag mở và tag đóng của một component. Trong project này, StepMessage không cần biết bên trong là text, nhiều <p>, hay một button. Nó chỉ nhận và render {children}. 

function StepMessage({ step, children }) {
  return (
    <div className="message">
      <h3>Step {step}</h3>
      {children}
    </div>
  );
}
<StepMessage step={step}>
  {messages[step - 1]}
  <div className="buttons">
    <Button onClick={...}>Learn how</Button>
  </div>
</StepMessage>

Gợi ý cho Reset

Nút Reset thuộc component Steps, vì chỉ Steps có quyền gọi setStep. Đừng đặt nó trong App trừ khi bạn chủ động lift state lên.
